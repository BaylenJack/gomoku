# 五子棋服务器端 AI 提示设计

日期：2026-08-09
状态：探索中（待确认）

## 目标

把 AI 提示从浏览器本地计算升级为服务器端计算，利用新加坡服务器低延迟 + 强算力提升棋力。

## 已验证的技术事实

1. **hint.js 是 UMD**，可通过 vm 沙箱在 Node 中加载（`computeBest` 可用）
2. **空棋盘 6ms 返回天元**（预算 1500ms / 40 万节点内）
3. **预算硬编码**在 computeBest 内部（`maxNodes: 400000, maxMs: 1500`）
4. 服务器是新加坡（47.82.0.187），Node 20.20.2，配置待查

## 方案对比

| 方案 | 深度 | 延迟 | 隐私 | 复杂度 |
|---|---|---|---|---|
| 现状（浏览器本地 Worker） | 6 | 即时 | ✅ 数据不出浏览器 | 已完成 |
| **服务器端 AI（推荐）** | 10-12 | ~200ms（新加坡→大陆） | ⚠️ 棋盘上服务器 | 需改造 |
| 混合（服务器优先+本地兜底） | 10-12 / 6 | 200ms / 即时 | 部分 | 推荐变体 |

## 核心设计（混合方案）

### 服务器端
1. **`/hint` HTTP 接口**（POST）：
   - 入参：`{ board: number[], color: 1|2, budgetMs?: number }`
   - 用 vm 沙箱加载 hint.js（缓存模块，避免每次重编译）
   - 调用 `computeBest`，预算调大到 **5000ms / 200 万节点**（服务器能力）
   - 返回：`{ x, y, ms, nodes }`
2. **防滥用**：限流（每 token 每秒 1 次）、限制请求体大小、白名单？——AI 提示本来就是特权功能，可以沿用 hint=1 的 token 校验

### 前端（hint.js 调用处改造）
1. 点提示 → **优先调 `/hint` 接口**（fetch POST）
2. 等待响应（新加坡 ~200ms）
3. **失败回退**：接口超时（3s）/ 断网 / 服务器 500 → 回退本地 Worker 计算
4. 本地 Worker 计算逻辑保留（兜底）

### 预算调整（关键）
- 服务器端把 hint.js 内部的预算从 `1500ms/40万节点` 提到 `5000ms/200万节点`
- 方式：**不改 hint.js**（避免影响浏览器端），在 vm 沙箱里注入一个"预算覆盖"——把 hint.js 里写死的预算通过一个可配置项读取

具体：hint.js 里 `const budget = { nodes: 0, maxNodes: 400000, t0: performance.now(), maxMs: 1500, visited: null }` 是硬编码。方案：
- **不改 hint.js**，而是服务器端在沙箱里包装：`performance.now()` 注入一个可控时钟，配合外部计时器强行打断？——不行，computeBest 内部自己检查预算。
- **更简单**：服务器端把 hint.js 源码做**字符串替换**（`maxNodes: 400000, maxMs: 1500` → `maxNodes: 2000000, maxMs: 5000`）后丢进沙箱。hint.js 是本地文件，替换是确定性的。

### 前端改动点
- `public/app.js` 里点提示的地方（目前调 hint.js 本地 computeBest）→ 先 fetch /hint，超时/失败回退本地
- 或者：在 `public/hint.js` 外面包一层 `fetchHint()` 函数

### 隐私权衡（需用户确认）
- 服务器端 AI 意味着**棋盘数据会发给服务器**（仅计算，不存储）
- 五子棋本来就有服务端（房间/落子都过服务器），所以棋盘数据本来就上服务器了——**没有额外隐私损失**！
- 所以"隐私"其实不是问题（棋盘本来就在服务器上）
